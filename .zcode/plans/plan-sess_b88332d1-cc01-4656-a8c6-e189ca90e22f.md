## 目标

1. 版本号 0.3.0 → 0.4.0（破坏性 Document API 变更 + 补丁器修复）。
2. 修复原生补丁器缺口：**当存在外部样式补丁时，结构新增（序列 append/insert、映射新增键、整容器替换）会从 dump 中丢失**。

## 缺口根因（已定位）

`rust/src/py.rs` `dump_value_with_patches`（py.rs:1615）：存在外部补丁时走 `collect_edits(suppress_structural=true)`。序列分支（py.rs:807-854）在条目数不匹配且任一 `_pyy_node_ids` 为 `-1`（Python 新建条目）时，回退成"整容器规范化重排"这一条覆盖 `node.span` 的编辑；该编辑与容器内部任何外部样式补丁按 `spans_overlap` 判定重叠后被**丢弃** → 新增条目丢失。映射分支则从不输出新增键（只遍历原生 entries）→ 新增键直接丢失。零宽 span 永不重叠（spans_overlap 严格不等式），所以"只在 Python 侧加插入补丁"无法可靠抑制原生回退（index 0 边界处会双重输出）——两侧必须配合修改。

## 实施步骤

### 1. Rust：序列结构路径按条目处理（rust/src/py.rs ~807-854）

重写 `suppress_structural` 分支：按索引遍历 Python list（`ids.get(index).unwrap_or(-1)`，顺带修复 zip 在元数据偏短时静默截断的隐患）：
- `id >= 0` 且有效 → 递归 `collect_edits` 并记入 surviving；
- `id == -1` → **跳过**（由 Python 侧插入补丁负责输出）；
- `id` 越界 → 保留整容器 `canonical_edit` 兜底；
- 删除逻辑（模型中不 surviving 的条目行删除，`entry_line_range`）保持不变。

效果：外部补丁存在时，原生侧不再产生与补丁重叠的整容器编辑，插入责任完全交给 Python 补丁；无外部补丁的路径（`dirty_dump_text`，suppress=false）不变。

新增一个原生单元测试（沿用 py.rs 现有 wrapper/handle 测试模式）：验证带 `-1` id + 外部补丁时不再产生整容器编辑。

### 2. Python：新增补丁生成（src/pythonizeyaml/document.py）

- `_iter_addition_paths()`：遍历数据树（用 `_raw_get` 原始读取 + `_pyy_entry_nodes`/`_pyy_node_ids` 元数据），产出**最顶层**新增节点路径（`id < 0` 的子节点；不递归进新增子树；跳过 merge 语义）。别名条目（registry 注册、metadata 为 (-1,-1)）会被产出，`_render_node` 对其渲染 `*anchor`，语义正确。
- `_new_sequence_item_patch(path, config)`：`_new_node_patch` 的序列孪生——父描述校验（sequence、非 flow）、`_render_node` 渲染新条目（含前后注释，剥离后重组）、`_rendered_is_inline` 决定 `- item` 还是 `-`+块、插入位置 = 最近一个**存在于源中**的前驱条目（`_describe(prev)["span"][1]` 推到下一行行首，连续新增链式回退）的行尾；index 0 则插在父序列首行行首（与 `_new_node_patch` 映射首键语义一致）。
- `dump()` 集成：`patches` 非空（即走原生合并路径）且 handle 存在时，遍历 `_iter_addition_paths()`，对未在 override 路径中处理过的路径生成 `_new_node_patch(...) or _new_sequence_item_patch(...)` 并追加；任一无法生成（如 flow 父容器）→ `needs_new_emitter = True` 走 `_emit_new` 全量重排兜底。现有 `unsupported_new_paths` 检查同步扩展为 `or _new_sequence_item_patch(...)`，使"样式化追加"从全量重排升级为局部补丁。`_build_patches` 首个循环同步用两者尝试，避免与 additions 遍历重复生成（override 路径去重）。
